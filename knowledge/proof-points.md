# Proof points

> **This file is empty of content on purpose.**

§6 requires every reference story to be flagged nameable or anonymised, and §9
bans the agent from naming *any* client not marked nameable here. The build has
no way to know which Hexaware clients have consented to being named, and
guessing would put a real client's name in an AI's mouth on a cold call to a
stranger. That is not a risk worth taking to save you ten minutes.

So: no proof points are drafted, and the agent currently has none to offer. If a
prospect asks "who else have you done this for in banking?", the agent says it
will come back to them. That is the correct behaviour until this file is filled.

## The shape to fill in

```markdown
### <short internal label>

- **Nameable:** yes | no
- **If anonymised, how to refer to it:** "a tier 2 Australian bank", "a large
  NZ insurer"
- **Sector / market:** BFSI, AU
- **The situation:** one sentence
- **What Hexaware did:** one sentence
- **The outcome:** one sentence, with a number only if the number can be sourced
- **Cleared by:** who signed off on this being said externally, and when
```

## Rules that apply whatever goes here

- A story marked `nameable: no` may still be told — with the client described,
  never identified. The agent must not narrow an anonymised reference to the
  point of identification ("a tier 2 New Zealand bank with about 200 branches"
  is an identification).
- Any number in an outcome needs a source in `approved-claims.json`, same as any
  other figure.
- A reference that is under NDA is not an anonymised reference. Leave it out.
